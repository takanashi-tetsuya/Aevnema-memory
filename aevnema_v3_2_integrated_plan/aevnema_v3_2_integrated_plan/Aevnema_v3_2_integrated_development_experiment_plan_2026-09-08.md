## 2. 本轮要一次性完成的范围

本轮不是只修一个 `deadline_at`，也不是再跑一遍八臂在线矩阵。它要交付一套能持续研究和运行的闭环：

**执行链稳定 → 取证可独立测量 → 精确/改写联想有可解释结果 → 与普通缓存比较 → 全量语料与独立评分准备完成 → 在具备条件的范围执行正式实验 → 给出真实能力边界。**

核心认知结构保持不变：Source / Episode / Concept / Association。新增或整理的对象仅限请求结果、运行策略、证据引用和实验元数据；不引入 belief、schema、dream 等新知识层，不以工程状态机替代联想研究。

保留两个自主学习理由：

- **recovery：** 一次寻找补回原本遗漏的必要证据，未来测试增量召回。
- **reuse：** 一次昂贵但正确的寻找形成可复用路径，未来测试同质量省工作。

一次寻找已经找齐时，边仍可通过降低后续搜索成本体现价值；不能因为没有增加新事实而将所有 reuse 边衰减成无用边。

## 3. 目标线、范围和统计边界

以下继承原 v3 研发目标，是待验证目标，不是已获得成绩。[S08]

| 目标 | 验收目标与必要说明 |
|---|---|
| 首次 Candidate Recall | 来源存在的主盲测 micro ≥99.5%；同时报告 macro、最差 family 和所有请求结果 |
| 实际 Delivered Recall | micro、macro 均 ≥99%；WholeQueryComplete ≥95%；不能仅扩大内部候选池冒充交付 |
| 精确第二次复用 | 首轮正确且依赖有效的固定回归集不新增证据损失；精确取证可做到 planner/embedding/reranker=0 |
| 改写及部分线索 | 改写来源存在集 Delivered ≥99%；快路径覆盖率单列，开发目标 ≥80%；欠明确无上下文任务允许澄清/不确定 |
| 边的独立效用 | 至少三个独立主题有可归因的召回或等质量工作节省；candidate-missing 与 present-dropped 分开 |
| 取证加速 | 同一 Q2、同质量条件下，边路径中位取证耗时不高于无边的 1/3，p95 不高于 1/2；不是 Q1 全回复/Q2 取证相除 |
| 调用约束 | contextual 匹配与每条边判断均 0 额外 HTTP；创建复用已有向量；启动恢复不请求云端 |
| 可靠性 | 技术失败、受限回答、未审结、未执行全部保留；端到端成功率单独报告，不用条件分数掩盖失败 |
| 负例 | 预注册严重错误身份/时间/因果升级、跨域泄漏、旧来源错误放行、cue 当事实等观察数为 0 才考虑扩大使用范围 |

近 100% 的目标必须限定题集、来源存在性、证据/时间预算和能力范围。无法保证任意未知问题都可回答。任务必须报告与目标的差距，不通过删题、改 gold、改变预算或选最好重跑使数字达标。

**精确检索复用、语义联想泛化、拟人记忆和完整聊天服务是四项分别验收的能力。** 同一冻结输入重复 30 次只提供时延/确定性样本，不提供 30 个独立语义样本。

# 第二部分　连续执行委派与边界

## 4. 一次委派的执行规则

代理收到本计划后，应自行沿依赖图推进，不在每个小修复后询问“下一步做什么”。先完成可独立执行的工作包，按里程碑汇报，不要求用户再次复制本文中的后续步骤。

### 4.1 可以连续进行的工作

在已有权限内：审阅当前代码与报告、建立隔离克隆、修改现有模块、运行本地回归/禁网 replay、收窄 Source 候选、核验导入残留、实现实验配置、执行已经获准且预算充足的模型批次、打包脱敏结果。已经完成且有当前版本回归的项目标记 `verified_existing`，不重复实现。

### 4.2 必须真实保留的边界

本计划不是新增的无限付费授权、正式库写入授权、人工 gold 签名或上线批准。代理读取已存在的授权与预算，明确本轮的有效范围；不得自行换 provider、模型、账户或借其他凭据突破限额。

缺少某类授权时，只暂停该分支，继续全部不依赖它的本地工作；把所有需要外部决定的事项汇总成一次 `DECISIONS_REQUIRED.md`。其中每项给出最小可决策材料，不能只写“等待人工”。

**Formal gold 未批准时：** 可以完成代码、真实非评分诊断、运行成功/时延计数、人工待审候选、全量静止快照、负例工具和报告；不能输出正式语义质量分数或代签。

**云预算不足/未授权时：** 本地实现、已保存输入重放、公开接口固定 provider 测试、数据准备和交付继续；不能伪造 fresh-live。

**存在严重来源/权限/写入 bug 时：** 关闭受影响新路由，在副本定位；不停止互不相关的数据审查与离线任务，不把失败请求强行完成。

### 4.3 批处理而不是无限重试

本轮最多安排 **3 个开发迭代批次**，每批包含“定位→最小修改→回归→已有输入重放→预算内新观察→汇总”，不是三个 HTTP 重试。相同缺陷最多两次有明确假设的局部修订；仍失败则保留诊断并转到其他独立工作，最终列出未解决原因。

历史 N11 系列、N12b/N12c 绝不覆盖或补写。新的代码版本可以执行新的预注册 trial，不必把“旧 trial 不重试”误解成“以后永远不能测试修复”；也不能只换目录、反复相同配置请求直到一次通过。

在一次冻结 trial 中每个臂只按其预注册次数运行。transport fallback 属于同一次请求账本，不是新样本。语义拒绝不得用 provider 重试洗成通过。预先安排的时延重复全部保留，不能挑最好值。

### 4.4 本轮状态只有必要的几类

工作包：`planned / in_progress / done / verified_existing / blocked_external / blocked_dependency / failed_documented`。

实验阶段：`not_started / running / completed / limited / failed / not_applicable / not_observed`。

阶段已完成不被随后失败抹掉；从未执行不记为 0 分。无需为上述状态建设新的通用编排平台，现有 JSON 进度文件和 runner 即可。

# 第三部分　开发技术规格

## 6. 统一取证边界：取证与回答共享实现，分开返回状态

### 6.1 目标调用链

```text
真实请求入口
  → 现有精确前置复用
  → 非精确局部联想提案（条件满足才用）
  → 必要的普通检索/缺槽修复
  → 来源绑定与贡献级选择
  → EvidenceResult 完成并落盘
      ├─ evidence_only：返回，不生成答案、不学习
      └─ full_answer：原答案生成/审核 → 合法 finalizer → 返回
```

优先扩展现有公开 `query` 的 stop-at/evidence-only 能力；若已有等价接口，直接复用。不得为了 Benchmark 复制一套与产品不同的“理想检索算法”。名称示例如 `stop_after="evidence"` 是**接口规格提案**，代理须在当前代码确认并实现，不得在未实现前声称可以直接执行此 CLI。

### 6.2 最小请求内结果合同

不新建知识库层；在已有返回对象中增加/复用：

```python
EvidenceResult = {
    "request_id": "...",
    "execution_profile": "input_frozen | live_evidence | full_answer",
    "requirements": [...],
    "evidence_state": "complete | partial | ambiguous | failed",
    "selected_refs": [...],
    "materialized_source_refs": [...],
    "unresolved_requirements": [...],
    "participation": {...},
    "executed_modules": {...},
    "actual_skipped_modules": [...],
    "timing_and_call_refs": [...],
    "learning_eligible": False
}
```

`complete` 仅描述当前运行时证据合同，不能取代独立 gold 的语义判断。绑定原文、估计支持当前问题、已审核当前回答三者使用不同字段，不将 `source_bound` 直接转成“所有主张已证明”。

evidence-only 无合法答案审核，不写新边、utility、mark_used 或成功学习回执。它可保存本地诊断文件。需要取证缓存实验时只写实验控制缓存，不写正式记忆；明确标签。

### 6.3 三种交付不能混淆

1. `evidence_materialized`：选中的当前原文已经组装，可供下一阶段使用。
2. `answer_input_sent`：哪些原文实际进入成功发出的回答请求；超时前已发送的也可记录。
3. `public_response_returned` / `adapter_sent`：核心或用户是否真的收到结果。

指标据此分别计算。evidence-only 返回的原文包是该实验的终点，但不是“已发给回答模型”；旧日志仅有 answer-input 对象、没有发送证据时，保持其原记录范围。

### 6.4 全路径回归

普通与 exact 命中、exact miss 回退、受限改写、多槽、证据不全、来源变更、超时、取消都使用相同绝对 deadline。固定 provider 仅替换网络边界；不要 patch 被验收的 `_generate_audited_answer` / `_exact_revisit_result` 来宣称完整控制流通过。

验证 exact 的 evidence-only 与 full-answer 两分支，防止 N11d 能取证而 N12c 一生成答案就 `NameError` 的断层。[S04]

## 7. 阶段检查点：请求失败不等于所有观察都未知

复用既有 full-local、answer-evidence 和 trace 框架，补足以下实际边界，不另建日志系统。

| 阶段 | 必记字段 | 随后失败时的保留方式 |
|---|---|---|
| 输入与需求 | 实际用户文本/可见上下文引用、解析来源、全部 required/optional 需求 | 原样保留，空候选需求不得消失 |
| 编码 | 逻辑角色→物理向量、文本 hash、模型空间、批次与获取来源 | 向量只保存一次，引用可离线读取 |
| 基础检索 | query/lane 的候选、分数、Top-K、是否独立 anchor | 不能由最终已选列表反推 |
| 边匹配 | 每 edge-slot 的门控、得分、截断和明确拒绝理由 | 匹配结束立即持久化，不等回答返回 |
| 来源与选择 | 来源版本、验证、贡献合并、逐步选择、被丢原因 | partial 与完整状态分开 |
| 证据交付 | 实際证据正文引用、预算、截断、回答/审核可见范围 | 后续 answer 失败不抹掉前面取证 |
| 答案/审核 | 版本、完整答案、每条被审主张、遗漏/拒绝/不确定 | 不将技术审核失败记成语义拒绝或通过 |
| 学习/结束 | receipt/edge/contract/manifest 可见时间、各终态 | 未观察字段为 unknown，未运行字段为 not_started |

边参与至少区分 `not_entered / evaluated_rejected / contributed / evaluated_no_increment / not_observed`。贡献、排名影响、被选择、被输出是不同层次；记录父 contribution，mask 可追溯。既有枚举可映射，不要求全部改名迁移。

每个 Q1、每个 Q2 臂分别原子落盘；整个矩阵收尾失败不能丢失已完成臂。日志 hash 只确认对象身份，不能替代必要原文。默认分享排除 answer-evidence；用户授权的实验包提供相关摘录并去除凭据、请求头及无关私密内容。[S02]

## 8. 需求、查询短语与向量：三者不能混为一谈

**需求定义要回答什么；检索短语定义怎么找；向量是短语的计算表示。**

保留单一整题 requirement 对应多个寻找短语的修复。用户只问直接原因，不因 planner 生成身份、时间、背景等探索短语就增加十个 required 槽；用户明确问多个独立事实，也不能为走 exact 而强压成一个槽。unknown/歧义本身必须保留。

相同规范化文本只编码一次，所有角色/slot 绑定完整保留。不同文本按批次编码不同向量；**一次 HTTP 批处理不等于只有一个向量**。Q1 保存的 whole 与 need 恰好相同可以共享，但这种案例不计作“双键独立区分能力”证据。

检查 `negation_hint=explicit_negation` 的定义：若它是校验政策，不应被解释成用户问题含否定；若它表示语义极性，必须由当前输入支持。未确认前不删除字段以绕过 gate，也不据字段名定罪。由代理在当前 resolver、提示词与测试中给出明确解释。

新提出但未存在于 Q2 输入的实体/答案不能用来造 query。部分线索的指代只能来自用户可见的当前上下文，不得从 Q1 答案、目标 ID 或 evaluator gold 补回。

初始只需一次共享 preparation：当前文本与已有必要子需求一起准备。后续才出现的新 follow-up 文本确实需要新编码时，使用预留有限预算并单列；不能伪称它包含于最初批次。

## 9. 复用路径：保留 exact，补足非 exact 的实际进入机会

### 9.1 精确复用不重新设计

保留 whole binding、rich requirement、scope、来源闭包、贡献级 selector、manifest 依赖边、重启恢复。精确缓存只是先定位可执行的已学习路径，不直接缓存答案。新增或未认识的要求不能继承旧 pass。

精确早停的前提是当前完整输入与合法精确合同一致，所有必要来源和预算仍有效。相同用户句子但上下文指代、权限、时间含义发生变化时，不是相同请求。计划/向量缓存命中与学习边命中分别统计。

### 9.2 非精确先提案、后决定能否省掉搜索

以下是本版**设计提案**，不是已证明当前实现具有的能力：

```text
exact miss
  → 当前问题/可见上下文的共享向量与轻量基础 anchor
  → 本地 cue/边提案
  → 读当前端点原文并检查版本、主体、时间/否定等约束
      ├─ 当前完整需求有可核验支持：有限前置取证
      ├─ 只证明主题相关：作为候选，继续普通检索或缺槽修复
      └─ 不匹配/模糊：拒绝该路径，不强行沿边回答
```

使用现有索引、matcher、target gate 与 selector。轻量 anchor 可以来自当前输入的稀疏/实体/小预算向量检索，不能先读取旧目标，再把它伪装成当前独立 anchor。若现有受限改写入口已经覆盖此职责，扩展其观测与测试，不另造重复入口。

双键是候选门控，不是语义等价证明。近似相似度只能增加“值得检查”的优先级，不能自动继承旧 requirement 的已支持状态；版本未变也不自动证明新问题等价。无法以现有本地检查确认的问题，允许走普通搜索，这样的回退是有效结果，但需计入完整成本。

### 9.3 两个位置的用途不同

- **前置提案/复用：** 用于减少后面的工作。不能依赖完整普通搜索结束后的 `unresolved_slots` 才启动。
- **残差补漏：** 普通检索后还有需求没解决时，利用相同图寻找缺失证据。

如果普通搜索已经找齐，残差路径不运行可以正确；不能由此推出学习边无价值。通过早/晚位置对照定位收益，不通过故意制造缺槽给边“创造成绩”。

### 9.4 最小控制策略

开发初始候选参数建议：每个请求最多检查 8 个候选端点，实际新增端点最多 2，先单跳；这些是待预注册的测试预算，不是已有最优阈值。保留同一 Source 的不同独立事实，不因来源相同全部去重。目标检查先于最终端点配额，避免不合格前列占满名额。

每个 family 记录 context 与 need 是否不同；若不不同，比较 CN 和单键时标记退化样本。开发阶段比较 W/C/N/CN/CN-shuffled，再决定是否确实需要两个键；不能因为“更像人”坚持实验中较差的结构。

## 10. 选择与缺槽修复：追求交付完整，不只拉高候选数

沿用贡献级集合覆盖。每条需求的直接来源候选、joint 前提与 alternative 分开；联合证据必须全部满足，不能第一条到齐就记满分。

本地 rank/support estimate 不是正式 gold，Source 校验不是当前问题蕴含判断。无法确认支持的关联端点可保留为候选上下文，不得自造 `supported_fact`。

必须记录最早损失点：来源缺失→表示缺失→需求遗漏→向量绑定缺失→基础召回→anchor→cue/Top-K→target→selector→prompt 截断。修复优先处理真实最早断点。

复用已准备的缺槽向量、稀疏入口或原文索引进行有限本地补查；保留同时间/来源/模态边界。原始候选中早已存在、只是被 Top-B 丢掉的记忆，应首先修选择而不是新增无意义边。

对大库做固定预算曲线，不能通过把全部语料发给模型得到“近100%”。候选预算、端点预算、原文/Token 预算分别固定并报告。无法在规定预算内完整交付时标记 `budget_limited`，不缩小需求分母。

## 11. 回答与审核：缩短无依据扩写，不增设审核塔

N12b 的已保存初答包含“排除其他动机”“无不确定性”等额外断言，但审核记录只列了一项直接原因。[S05] 这是审核覆盖不足的观测，不应改写历史 `valid=true`；该状态不升级成独立金标准。

新版本默认单事实回答只回答必要主张及合适来源限定；不强制输出“必要的联想路径、其他解释、排除理由”。复杂问题才按实际需求展开。程序 trace 中的路径与语言模型写的“联想路径”必须分别显示。

继续现有一个答案审核阶段，要求列举并检查答案实际包含的可核验断言。额外排他/因果/时间/身份断言未被审查时，不得仅因一条核心事实通过就报告整段完整通过。优先从生成端减少不必要主张；不新增第三个审判模型来弥补固定冗长模板。

answer 和 audit 使用同一份预算内必要原文与 speaker 引用；可有不同系统提示，但实际证据差异显式记录。修正复核绑定当前答案版本与证据版本。没有足够来源只能限制回答；查不到其他理由不等于其他理由不存在。

保留一次有限修正、总截止时间和收尾准入。技术异常、语义拒绝、审核未完成、证据型降级、正常审核通过分别返回。未核验/超时/取消不授权学习。证据型降级让用户知道已找到什么和仍缺什么，不冒充已回答完整问题。

## 12. 云端成本、重排和可靠性

N12c 本地初始检索约 0.49 秒的已完成样本，重排约 38.68 秒、复合回答约 58.73 秒。[S04] 这支持优化与解耦的优先级，但不单独证明 provider 故障原因或每项审核都无效。

### 12.1 运行策略分栏

| profile | 云端准备 | 本地检索/联想 | 答案/审核 | 学习 |
|---|---|---|---|---|
| synthetic_regression | 禁止 | 真实算法+可控数据 | 网络边界固定返回（明确合成） | 只在临时测试库验证契约 |
| recorded_replay | 禁止，使用确实保存的输入 | 重跑被比较模块 | 可重放真实完整响应，不填缺失 | 默认关闭；公共 finalizer 重放测试另标 |
| prepared_evidence | 每个 Q2 上游准备一次，预算内 | 各臂相同输入，真实重跑 | 不运行 | 关闭 |
| live_evidence | 包括当前正常准备的真实成本 | 真实路由 | 不运行 | 关闭 |
| live_answer | 实际成本 | 真实路由 | 现有审核标准 | Q2 对照关闭；新 Q1 明确开启 |

只停答案并不保证取证零云端：LLM planner/reranker/coverage audit 也须记账。纯本地机制层使用已保存、经过依赖校验的共同输入；live 层按真实调用计算。

### 12.2 重排策略做受控消融，不全面删除审核

保留冻结旧策略作对照；开发比较“当前策略”和“局部-first、仅确定存在选择歧义时启用一次受预算约束的重排/覆盖核验”。BGE reranker 是独立可选因子，不能把 LLM rerank 与 BGE 混称。使用新模型/本地未部署模型需要独立授权与验证，不属于本计划默认变化。

不因问题有“为什么”二字就自动膨胀为全剧情推理，但也不因相似度高便取消必要核验。是否简化应由开发 Source 主张检查与负例结果决定。已保存的失败/timeout 仍保留，不改原参数来追溯性计算“原来能成功”。

### 12.3 预算规则

使用现有绝对 `DeadlineBudget`，精确与普通路径、排队、fallback、修正、审核和收尾共享。保持原诊断 120 秒与每次请求 25 秒、零一般重试作为比较初始值；任何调整须新 profile，并在所有配对臂一致，不能把不同控制器的差异算给边。

在尚无更明确授权时，建议新的小型诊断批次上限为 **40 次实际 HTTP**（含准备、失败、回退、JSON repair、隐藏嵌入分批），并以现有明确剩余授权的更低上限为准。该数字是提案，不是本计划替用户授予的新费用权限。全量重导和正式大规模 fresh-live 单独有已有/新增审批的总额，不能从这个配额默认为无限扩张。

先估算整个批次最坏请求数，预留每个被准入 live-answer 的审核尾部。相同模型连续 3 个技术失败或同批 2 次总 deadline 失败，停止该 provider 的新付费任务并转离线；不自动换模型、加并发、延长超时。停止条件是本版建议，冻结后执行，不根据分数选择是否触发。

仅当暂停原因已被明确修复或外部服务状态在既有授权内允许下一批验证，才以新 batch 继续。失败不会阻塞无云工作，更不会被后台无限重试。

## 13. 学习与 utility：成功状态不是自证

保留公开 Q1→审核/证据合法性→finalizer 的学习入口。历史 N11d、N12b 的合法冻结状态可用于开发接线与回放；不同数据库里的 `edge 121` 不是同一全局对象，所有记录使用 `(snapshot_id, receipt_id, edge_id, source_fingerprint)`。

Q2 机制/配对实验全部只读，不写新边或 utility，避免前一个变体教会后一个。实际长期学习实验另开轨迹；创建回合不算独立成功，自生成回答不洗白成原文，扩散节点不得同轮级联证明自己。

效用观测分为：独立证据增益、同质量工作节省、无变化、有害、技术未知。技术失败不当负向语义样本；仅边被用过不加事实置信度。来源失效可退休路线，但不删原始经历。

N12b 扩展断言审计覆盖疑点，不逆改历史学习回执；禁止把其当最终质量真值或放大 promotion。跨主题正式新 Q1 使用修后输出范围与当前核验，记录真实新建结果。

# 第四部分　实验程序与可解释对照

## 14. E32-00：证据保全、当前代码资格与执行清单

读取两仓库当前状态、17 项新回归实际覆盖、历史冻结包与本轮需要的数据库/向量。完成源码位置映射；版本不一致不覆盖，只记录差异并继续在可控工作分支。

验证已有 Source 绑定、重复/多行拒绝、预算原因区分、伴随日志分享排除、answer/audit 一致、typed manifest、exact deadline、项目 SQLite 工厂等回归。[S02][S04] 已通过当前版本检查标记已存在。

修复 exact full-answer 的固定 provider 公共入口测试；范围是已确认断点，不再大规模重写 transport 或 journal。

输出：当前版本/补丁与配置、测试原始结果、资产可用性、映射后的真实命令表、后续可执行工作包列表。不能只提交“校验器能拒绝输入”就宣布全部实验准备完成。

## 15. E32-01：将 N12c 失败重组为阶段证据，不改历史

从现有原始 JSON/伴随文件提取每臂已有观察；保留答案输入 E18/E19/E31/E32 的实际原文和选择理由。输出每条必要主张在候选、选择、交付、回答、审核的最早状态；缺失写 unknown。

按相同 request/call_id 去重汇总取证/coverage-audit/答案/答案审核调用，校验总数；使用终端异常类型分类，不以 `completed` 字段推断质量。特别解释改写遮罩为什么选 E19，核心问题为何原选择 E18：从 Source 对照支持关系，不能只因 ID 不同判错。

对 N12b 初答的扩展断言制作一次既有材料审核覆盖表；不需要为此调用新模型。它用于改模板和覆盖测试，不给历史资料新增通过章。

输出：阶段矩阵、逐主张对照、调用总账、未记录字段；该任务结束后继续实现，不再次只让用户阅读一份复盘。

## 16. E32-02：同章 Q2 的共同输入、取证级成对实验

使用已验证的 N12b 学习快照，不重新生成 Q1。保留四个历史 Q2，增加一对“中性可见上下文+相同部分线索”与“话题切换/无上下文”诊断，历史四项不改写。[S04][S09]

中性上下文只指定正在讨论的事件与人物，不包含原因、答案、目标 Episode 或 gold。文本在执行前冻结，两个对照完全一致。无上下文任务的正确目标不是强行命中旧记忆，而是对歧义保持边界。

### 16.1 三种冻结精度

- `input_frozen`：固定 query/context、实际生产解析的需求与向量、数据/初始图，分别重跑基础检索+候选联想+selector。
- `candidate_frozen`：固定在边注入之前的基础候选及贡献，分别重跑 matcher、target 与 selector，定位边/选择作用。
- `live_evidence`：从实际入口含准备开始，独立运行到取证返回，报告服务成本与失败。

共同输入只能包含边处理之前可获得的材料。不得把有边臂返回的 target/答案/selected IDs 注入遮罩组的需求生成；evaluator-only Source 定位不能成为生产查询。

如果旧 artifact 只有向量 metadata 没有向量数组，不能从 hash 伪造；到本机原引用找，缺失则明确重新准备并记新成本。planner 无完整响应时，不从 gold 写个更好的替代计划。

### 16.2 最小配对

每个 Q2 最少运行当前边可见、仅本轮边遮罩两组。基础渠道保持可用。同一 Q1 学习快照独立克隆，各臂禁学习；mask 移除对应 contribution 及其派生路径，manifest/cache 不能绕过，但独立 dense/sparse 找到的目标仍保留。

取证实验停止于 EvidenceResult，强制无 answer/audit/finalizer。既有 LLM rerank 输出若作为冻结上游，只能在其输入完全相同、未包含 treatment 新端点时共享。若处理的是不同候选集合，不能偷用旧重排；选择共同候选 union 只可作为单独的 selector 诊断并明确其改变了被测问题，不称为完整在线因果效果。

本地确定性重复 3 次确认输出一致；这些不算新增语义样本。每个变体必须得到一个可解释对照或准确的输入/技术阻塞，不能因答案生成失败留空。

## 17. E32-03：决定非精确联想在哪里生效

在 E32-02 可重复输入上分开比较：

| 位置臂 | 行为 | 解释 |
|---|---|---|
| P0 普通基线 | 不读本轮边 | 当前正常取证基线 |
| P1 late residual | 搜索后缺槽才读边 | 补漏而非前段省时 |
| P2 prepared early | 需求/向量准备后、宽搜索前提案 | 检验少做宽搜索/重排，不宣称省掉了准备 |
| P3 query-first probe | exact miss 后用当前已知文本/上下文及轻量 anchor 提案 | 尚未被支持的早期泛化提案；只在本地可确认需求边界时早停 |

P3 是受控开发策略，初始默认影子/取证诊断。不能放宽 exact 字符串检查，不能把所有改写硬投影到旧完整需求。若 P2 已有稳定收益而 P3 大量误激活，保留 P2 并报告范围，不为更高加速强行上线 P3。

位置选择固定后，在相同预算比较 W（纯权重）、C、N、CN、CN-shuffled。打乱 cue/端点绑定的分布和数量保持；若打乱仍然一样好，不能宣称语境学习有作用。一次只改变位置或评分维度，不跑不必要的全笛卡尔积。

若全部候选已覆盖且不存在可节省工作，结果可为 no-op；继续更大干扰或独立主题实验，不删正确基线来强行制造增益。

## 18. E32-04：普通缓存与边的公平对照

| 臂 | 允许保留 | 仍须执行 |
|---|---|---|
| B0 普通重搜 | 仅共同静态索引 | 正常准备、检索、重排策略 |
| B1 请求内向量复用 | 该 Q2 内的共享向量 | 其余正常工作，预备调用计入 |
| B2 历史计划缓存 | Q1 合法形成的需求/计划（只在有效范围） | 重新取证与来源检查 |
| B3 普通来源校验型证据缓存 | Q1 的 EvidenceRef 集合、适用 exact 键与来源依赖；不含答案 | 同等 scope/source/budget 校验，无边 required |
| B4 前置边复用 | 原学习边+manifest | matcher、target/source、selector |
| B4M 边遮罩 | 除被遮罩依赖外其他状态与 B4 一致 | 正常 fallback 成本必须记录 |

B3 不是伪装成边的新模块，只是必要基线，可置于 benchmarks/control_cache。不能故意不给 B3 缓存原文指针或故意多执行一轮模型，让 B4 取胜；也不能让 B3 跳过 B4 必须执行的有效性检查。

精确同文先测 B0/B3/B4，剩余用于贡献分解。新词改写时，B3-exact 正常 miss；若比较语义缓存，明确使用相同编码、过滤与预算，不手工给缓存更差匹配器。

同一 Q2 顺序预先随机或交错，分本地取证/云端含准备/完整回答；每种重复数冻结。建议本地每臂 30 次用于时延分布，真实云端首批每个预注册代表对照一组，不用重复 30 次烧预算。冷启动、已建索引、持久化缓存三类单列，OS 进程重启记录 PID/启动身份，不把 new app 自动称真实重启。

精确缓存若与边等效，结论就是精确复用主要来自有来源的路径/证据缓存；图的额外价值留给非同文、多入口、多跳组合，不为维护设计偏好掩盖这个结果。

## 19. E32-05：多槽、跨来源和三种遗漏

先从三个独立主题的小集合开始，题型至少包含直接实体、自述/推测边界、明确时间或联合证据。主学习 Q1 通过公开入口，非人工预置；历史已保存合法 Q1 可作为开发轨迹但不当新盲测。

每个主题冻结 Q1、同文 Q2、两种未用于学习的改写、带中性上下文部分线索、同实体换关系/时间负例。独立主题不能只换同一文件中的题号；按事件/来源近重复聚类记录。

额外构造真实 Source 支持的多槽请求：旧槽+新槽，两个不同主体，联合前提，多个合法替代来源。reuse 命中旧部分不等于整题完成；必须对新部分继续搜索并保持完整分母。

区分三类瓶颈：

1. `candidate_missing`：必要事实未进入基础候选，边能否增量带回。
2. `present_dropped`：候选已有但被选择/截断丢掉，贡献选择是否补回。
3. `already_complete_costly`：原来已找齐，边能否同质量省工作。

开发可用合成小图验证前两类机制，真实成绩不能靠删除正确端点或故意破坏基础检索制造。若只有一个类型有成功，就只报告这个范围。

## 20. E32-06：少量完整答案与实际聊天入口

只有取证对照已有结果后，选择预注册的正例、无收益例、近邻反例各自进入有限完整回答样本，不能只选获胜案例。实际调用预算不足就先执行最小配对，其他标明未执行；不更换模型或跳过必要审核凑满。

在同一运行策略下比较相同 Q2 的两臂，固定答案提示和证据预算。记录审核覆盖率、答案主张正确性、技术成功、限时成功、最终消息发送。保持 Q2 不学习，避免评估污染。

Aevnema 聊天层必须有一条公开 adapter→request planning→memory→answer→发送→学习可见的回归。核心取证成功不能代替聊天层成功。记录四个时间：Q1 核心返回、实际发送确认、学习事务提交、索引/manifest 可读。即时 Q2 按真实事件触发，不能静默等待 ready 后再命名即时。

不为该验收另造聊天恢复系统；重用现有 journal，观察失败/取消边界。正式用户流量及自动 promotion 仍依第 28 节独立批准。

## 21. E32-07：19 项独立 Source 候选收窄与评分准备

当前 19 项是历史检索候选，而不是天然的 19 条成立事实。[S06][S07] 每项需由代理主动提出以下最小审核包：

```text
原候选 ID → 一个明确的原文主张（必要时拆分或建议拒绝）
主张的主体/宾语/关系/时间/转述或推测边界
最小原始字段与精确 code-point span + hash
必要的邻近发言者/指代上下文及其来源
为什么支持、为什么不足或有什么争议
建议 accept/split/reject/needs_context（代理建议，不是人工签名）
```

不再只输出数千行重复全文，让用户自行从头寻找答案。完整原文仍按哈希索引保存，主审阅表每项只呈现必要范围。无法恢复 speaker 绑定时明确不足，不能从 LLM 摘要补身份。

一次性提交全部候选处理建议与最少待决问题。人工接受前保持草稿，不能假造 reviewer。批准的子集可用于其明确范围内的开发质量检查；正式盲测还需独立 split，不因一个 atom 获批就整包正式化。

Gold 只由 evaluator 读取，runtime 不能访问目标 Episode/答案/span 标签。随机运行题的顺序，评价者可盲于 arm 标签。报告 reviewer 分歧和修订版本，不把 LLM judge 当独立真值。

分组隔离的是开发/校准与最终 holdout 的事件、近重复来源，不是要求同一 holdout family 内的 Q1 与 Q2 来源互不相交。机器人先经历 Q1 再回忆 Q2 是任务定义；不能把它禁止，也不能把 Q2 答案用来训练 Q1。

用户指定的大规模导入是主任务，不取消，也不无限期等 gold 全部批准。读取本机已授权 `event/main/favor` 根，保持原始文件只读。

### 比较矩阵

- 数据：K_old（可恢复旧库）、K_diag（当前近全量诊断库）、K_full（全部有解释处置的接受库）。

- 题集：G_common（共同来源事实）、G_expanded（新增事实及跨新旧片段联合）。

## 23. E32-09：盲测、能力统计与拟人特征

分阶段样本建议沿用原 v3：开发集先小后扩，最终目标 40 个开发 family、至少 100 个独立 holdout family、300 条分层负例、300 轮受控会话。不是要求所有题每个臂都重复云端生成答案；完整检索集可使用准备后冻结输入，端到端回答按预注册分层抽样，并分别标明证据级与服务级成绩。

预算不足时提交已完成真实样本数、置信区间和缺口，不能缩样后称达到原计划。对使用过 N11d/N12c 调参的题，只作开发/回归，不能变成最终 holdout。

拟人指标采用可观察任务：

| 特征 | 对照与观察 |
|---|---|
| 一次学习 | 未经历/经历同一 Q1 的隔离副本；新边真实生成；第二次从新线索取回 |
| 部分线索 | 有中性上下文、无上下文、冲突话题三组，匹配范围与不确定性处理 |
| 个体化 | 相同原始库、两个隔离 agent 的不同经历；比较稳定检索入口，不把随机输出差异算人格 |
| 连续性 | 清会话、清进程缓存、真实重启；保留来源/边，记录启动开销 |
| 纠正 | 原 Source 修改、追加相反新 Source、用户偏好随时间变化分别测；旧经历仍保留来源 |
| 遗忘与竞争 | 低效/过时/有害路径衰减或退休；原始事实仍可普通回查，不随机删 Source |
| 组合回想 | 单跳有证据后，独立实验两跳/多入口共同恢复；不把路径当因果证明或同轮建边证据 |

双键/单键/无学习/普通来源校验缓存分别比较。若只精确复问有效，能力名称保持“持久化精确检索复用”；不提前宣称自然人式记忆或完整人格。

## 24. E32-10：规模、并发和故障恢复（只测相关边界）

优先真实当前库与逐步扩展库，记录 Episode、Source、cue、edge 各自规模，不只把 564 文件当索引规模。之后可做合成 1k/10k/100k 边压力，标明不是语义质量样本。

先并发 1，再 4/8；达到授权/硬件资源边界即停，不默认执行百万边×高并发×全部 slots 的笛卡尔积。记录 RAM、索引加载时间、SQLite 锁等待、BLAS 线程与每请求扫描量；索引压缩/ANN 是独立后续优化，不与联想机制同时改以致无法归因。

在本地假 provider 模拟 timeout、429、慢流、排队、取消和迟到响应；检查请求数不随边数增长、失败后业务零写入、其他臂结果不丢失。范围限当前调用链，不新增通用跨机一致性框架。

# 第五部分　指标、原始轨迹与交付

## 25. 评分与因果归因的统一定义

每个请求的全部必要 evidence clauses 在运行前或生产需求解析时冻结。生产解析漏需求由独立 gold 发现，不能以 production slots 少就减分母。

| 指标 | 定义与注意事项 |
|---|---|
| SourceAvailability | 所需原始材料是否在该快照内；缺失单列且保留全请求任务结果 |
| RepresentationRecall | 有来源的事实是否有可查表示或原文回查入口 |
| CandidateRecall@K | 全部已扫描渠道候选是否覆盖 gold；包含错误关系同名词不算 |
| SelectedRecall@B | selector 保留的完整 joint/alternative 支持 |
| EvidenceReturnRecall | evidence-only 公开返回的实际原文包覆盖率 |
| DeliveredRecall | 真正进入回答调用的原文覆盖率；不把 selected 列表冒充 |
| AnswerClaimRecall | 回答正确表达的必要主张，保留转述/推测边界 |
| AuditCoverage | 回答可核验主张中实际经过审核的比例；不能只数 audit.valid |
| UnsupportedClaimRate | 无依据的额外断言；严重类型与一般扩展分开 |
| ServiceSuccess / LearningReadyRate | 所有预注册机会中实际成功回复/实际合法学习就绪的比例 |
| FastPathCoverage | 新输入中无需宽搜索的成功比例；miss 回退的全部成本也记入 |

成对边效用以同一个 Q2、同数据/预算/准备输入为基础：`recall_gain / equal_quality_less_work / no_increment / harmful / incomparable_technical / not_observed`。同时报告受控机制层和 live 服务层，不把一次网络更快当算法改进。

对于同文来源校验缓存，命中可很好地解释加速；图的独立优势需来自改写、多入口/多跳、较高复用覆盖或降低重复存储等被实际测到的维度。

时间分别列排队、准备、检索、联想、source check、选择、回答、审核、提交、重启。provider 计时是另一种视图，不加到包含它的 engine phase 上。CPU/本地-only重复用于计算分位数，live 单次仅作样本，不稳定时明确区间和外部影响。

统计按 family/事件聚类配对计算区间；同源多改写不是独立语义试验。零严重错误须附样本数、分布与覆盖范围，不能解释成总体零风险。

## 26. 全过程 case report：必须让用户看见实际回想

每个 family 自动生成以下七栏，来自事件，不由模型事后编故事：

1. **请求：** Q1/Q2 原文、可见上下文、模式、预算、代码/数据库版本；独立 gold 在 evaluator 栏，不送入 runtime。
2. **找的过程：** 每个需求、每个 lane 的候选与 rank、独立 anchor 的来源、截断点。
3. **联想过程：** cue 依据、context/need 分数、每个 gate 及端点检查、进入或拒绝时间；显示不曾执行的模块。
4. **交付：** 逐步 selector 选择、实际原文与 speaker/版本、为何丢掉其他证据、是否进入回答调用。
5. **学习：** Q1 的创建理由、端点、receipt/contract/manifest、提交及 ready 时间；不假设所有 edge121 都同一条。
6. **对照：** 有边/遮罩/缓存的实际证据、模块、HTTP、时间；基础渠道仍找到的相同目标明确显示。
7. **结论：** 当前证据支持哪一种能力，哪个阶段失败，未测项与后续依赖；不是一句“全部通过”。

原始大对象按 hash 保存一次；向量使用安全数组格式，加载禁 pickle。报告可脱敏但必须保留足以分析的授权原文，不把全部内容换成 hash 后仍称全过程可读。

## 28. 完成条件与发布边界

本次完整委派的完成，定义为：所有工作包均有真实状态与证据；无外部依赖的任务已执行到验收或有明确失败；依赖人工/预算的任务具备下一次可直接继续的材料；已具备条件的实验已按预注册运行并报告。**不能仅交付准备好的 manifest 就称全部执行完成。**

能力决策分级，不要求全有或全无：

| 结果 | 允许的结论/下一步 |
|---|---|
| exact 稳定，改写未知或退化 | 保留精确模式；不宣称语义联想通过 |
| 取证有收益，回答服务不稳定 | 宣称相应范围取证收益；服务完成率仍未达标 |
| 单库好，大库下降 | 保留真实全量下降，定位候选截断/热点/表示；不能改小库作最终成绩 |
| 缓存与图等效 | 采用更简单且同样有效的配置，图研究转向其未覆盖能力 |
| 独立质量目标未达 | 报真实数值及根因；有界开发迭代，不改评分标准 |
| 严重来源/权限/事实错误 | 停用受影响快路径，保留普通可用能力，正式推广 No-Go |
| 全部相关质量、成本、来源与聊天链通过 | 生成发布候选建议；真实生产/灰度仍需要已有相应授权 |

发布按 exact、受限改写、多槽、private/creative 分范围。影子只记录 treatment，实际回答 masked，不用 masked 的审核给 treatment 授权学习。用户未批准的正式库和线上流量不写、不发。

## 29. 自动继续与遇错处理表

| 事件 | 代理应立即做什么 | 后续继续什么 | 何时需要汇总给用户 |
|---|---|---|---|
