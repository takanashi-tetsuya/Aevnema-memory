# 一次性执行入口 — Aevnema v3.2

这是用户一次委派的完整工作范围。阅读主计划与执行清单后，连续推进全部依赖满足的任务，不在每个局部修复后只回复“下一步应该……”。上一条未转发的零散建议已全部并入。

## 首先做什么

打开 `Aevnema_v3_2_integrated_development_experiment_plan_2026-09-08.md`。本包的 JSON 是计划规格，不是已实现 CLI、已授予费用额度或实验成绩。先在当前工作区映射真实入口、配置、现存回归与授权；不要pull覆盖本地变更。全部历史trial只读。

## 一次执行到哪里

本轮要连续完成：

**公共取证/回答分界与阶段结果 → exact完整回答回归 → 同章冻结输入取证对照 → 非exact早期提案/残差补漏 → 单键/双键与缓存消融 → 跨来源自动学习和多槽 → 全量残留处置、gold收窄与正式条件准备 → 预算内的完整聊天和独立评估 → 总交付。**

N11d精确取证已通过，不推倒重做。N12b已有合法Q1学习状态可供开发，不因每次Q2失败重发Q1。N12c包含45次HTTP、一个完整结束臂，不能再原样扩展同一高失败在线矩阵。

## 自主执行约定

- 使用20个工作包作为内部队列。完成一个就自动检查依赖并进入下一个；W10/W11资料工作与核心代码线可并行，禁止同库并发导入和查询。
- 已实现并有当前版本证据的项标 `verified_existing`；未实现不能用方案说明冒充完成。
- 一个臂失败立即保存阶段记录并继续不受影响工作。不回填旧日志，不把未知记false，不把绑定原文当作已证明当前主张。
- 云预算/人审只暂停对应分支。所有必要外部决定集中进 `DECISIONS_REQUIRED.md`，提供具体最小材料。不要为每个小任务让用户重新授权或重新写提示。
- 只使用已有明确授权的模型/语料/网络。建议的40HTTP诊断批上限不是新的授权；存在更低剩余额度从低，没有明确授权先做全部本地工作。
- 开发最多3批，同因局部修订最多2次；原始失败不可覆盖，新假设新版本新目录。允许预注册的新版本实验，不允许相同配置反复试到成功。
- 人审缺失不代签；把19个历史候选真正收窄为主张+原文+span+发言者依据+争议建议，不再只发6000行全文等待人自己找。
- 不新建belief/schema/dream层，不扩展journal/权限框架，不硬编码剧情答案，不添加per-edge云调用，不擅自发布到正式库。

## 四个必须避免的替代品

1. 本地fixture通过 ≠ 真实语义成功。
2. 同文缓存快 ≠ 改写/部分线索已泛化。
3. source_bound或audit只核一条 ≠ 整题所有断言正确。
4. selected IDs ≠ 实际原文已进入回答提示。

## 结果必须怎样交付

取证实验先独立产出事件和原文，答案超时不得抹掉其结果。每family给Q1→创建→Q2→mask/cache的实际路径和成本；不让模型事后补写“思考过程”。完整结果包括代码/测试、取证迁移、缓存速度、全量语料、gold待审、拟人序列、失败和外部阻塞。

全部工作完成，或剩余工作确实只因外部权限/预算/材料被阻塞时，交付真实脱敏ZIP和campaign_state。不能只回“已修一个问题，下一次再做另一个”。会话资源不足时落盘续接状态，下次仍用同一计划，不要求用户重新调度。
