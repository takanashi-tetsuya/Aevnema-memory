# 领域规则去硬编码报告（2026-09-01）

## 结论

运行时已经删除此前为特定剧情问答逐步追加的主要特殊规则。当前检索、增长和答案审计不再识别或
强制生成 `political_precondition`、`historical_support_context`、`role_evidence_bridge` 等固定剧情关系，
也不再因为“政变、暗中协助、成功渗透、直接执行者”等剧情词组建立专用答案槽、候选保留通道或审计
豁免。

保留下来的限制是领域无关的证据不变量：身份不能从相邻实体转移，相关性不能自动升级为因果，推测
不能升级为事实，不同观察不能在缺少连接证据时共享具体机制。这些限制适用于剧情、百科、聊天记忆和
普通文档，不依赖任何作品设定。

## 删除内容

### 查询层

- 删除控制边界、内部权力、政变、现场执行者、暗中协助、政治前置、哲学隐喻、故事首尾、反驳模板等
  关键词分支。
- `_structural_queries` 现在只接收查询解析器已经明确提取的关系、时间和因果约束。
- 用户加引号的原文锚点仅生成通用 `__answer_slot__`，不再从词面猜测所属领域或答案结构。
- `__constraint_slot__` / `__answer_slot__` 成为候选预算保护的唯一显式入口；普通剧情词不再获得隐藏优先级。
- 删除答案审计中根据“政治铺路、机制未知”等固定措辞自动把 `unsupported` 改判为
  `supported_inference` 的代码。

### Association 增长层

- 删除必须先写 `role_evidence_bridge`、再写跨事件桥的固定边顺序。
- 删除 `political_precondition` 和 `historical_support_context` 的专用写入条件、专用禁词表和专用
  `claim_level`。
- `relation_key` 重新变为描述性自由字段；系统不要求任何领域专用键。
- 删除“通过内部政变准备继任职位即可自动视为某组织高层”的确定性例外。职位与成员身份现在必须有
  可见证据，或由模型作为明确、可审计的推论处理，不能由 Python 剧情模板直接放行。
- 增长提示和两轮审计改为统一检查主语、谓词、宾语、方向、身份、时间、模态、认识状态和前提完整性。

### 证据选择与答案层

- 删除“控制者—被控制组织—现场行动”“直接执行者—此前政治支援者—渗透边界”等固定 coverage
  拆分模板。
- Coverage Selector 只按独立事实槽、合取条件、时间两端、因果链、反证和认识状态工作。
- 答案与跨观察审计不再使用袭击、爆破、渗透、政治合作等领域例子或判定模板。
- 修订提示只要求删除没有可追溯证据的身份、因果、使能和具体机制，不规定应改写成某一种剧情结论。

### 测试层

- 删除或改写要求上述剧情模板必须存在的测试。
- 新测试确认无结构化 intent 时不会凭问题词面创建领域槽；结构化 intent 仍会得到请求级约束槽。
- 新测试确认模型审计的 `unsupported` 不会再被 Python 根据答案中的领域关键词擅自翻转。
- 修复三个测试模块对 `helpers` 的非包导入，并阻止 `test_config` 工厂被 pytest 当成测试收集。

## 保留内容及原因

- `BlueArchiveJsonAdapter`：这是输入格式适配器，不是剧情知识或推理规则。它只负责读取该 JSON 结构、
  多语言文本、发言者和原始脚本字段。其他 JSON 仍可走通用 JSON 解析。
- generation：保留。它记录结论距离直接证据的推断代数，与 confidence 分离。
- evidence origin / epistemic status：保留。它们用于区分原始文档、导入者补充、系统推论、转述和猜测。
- 身份与因果证据约束：保留。删除这些约束会让任意知识库出现成员归属转移、主客体错置和跨文档因果
  幻觉，并不属于“让网络自由生长”。
- 时间线隔离和 source_key：保留。不同观察默认不共享具体事件机制，但仍允许在有证据时建立关系。

## 当前仍存在的工程问题

这次删除的是领域特化规则，不是完成整体拆分。`retrieval/engine.py` 和 `llm/prompts.py` 仍然很大，
查询计划、证据覆盖、图扩展、答案生成和审计还集中在少数文件中。后续优化应把策略改造成请求级、
不可变的 `RetrievalPlan` 与独立 `RetrievalQuality`，通过评测决定是否升级检索，而不是再次向大提示词
追加新案例规则。
