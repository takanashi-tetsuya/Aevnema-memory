# 证据驱动检索升级实验报告

日期：2026-09-01

## 1. 结论摘要

本轮实验验证了一条可行的通用路线：系统不在检索前依靠“为什么、关系、第一次”等词表决定 light/standard/deep，而是先进行低成本语义检索，再由证据充分性判断产生缺失事实槽，只有证据不足且缺口仍可能在知识库中时才扩大候选集并进行图扩展。

核心结果：

- 120 条跨中文、英文、日文样本中，基础知识检索的预期证据命中率为 98.33%（59/60）。
- 单独使用 BGE 最高分不能可靠判断“是否足以回答”。`0.05` 阈值仍有 5 个误接收和 2 个误拒绝；最佳样本内阈值也只有 95% 粗标签准确率。
- Qwen3.5-9B 第三版证据判定在 60 个负例上产生 0 次“证据足够”误判；在 60 个预期知识问题中有 53 个可由首次候选直接回答，7 个被判为不足。
- 对初检不足的 9 个案例执行“缺失事实槽查询 + 两跳图扩展 + 80 候选”后，6 个稳定升级为可回答。
- 28 个“人物相关但具体细节未收录”的安全对照经过相同深搜后，仍为 0 次错误补全。
- 深搜复核重复两次，37 个案例的可回答性判断完全一致；只有 1 个案例在 `discard` 与 `uncertainty` 之间变化，不影响是否允许事实回答。

因此，证据驱动升级带来了真实收益，而且没有在本批安全对照中放宽成“相关文本越多就越敢回答”。但该机制尚不应以独立 LLM 审查调用直接接入所有在线请求：完整串行链的延迟过高，应把证据合同合并进最终回答调用。

## 2. 名词定义

### 2.1 Domain Probe

对私人记忆、公共记忆、剧情知识等候选域进行低预算查询。Probe 的目标是取得少量可能有用的候选，不负责决定候选是否足以证明答案。

### 2.2 相关性与证据充分性

- 相关性：候选与用户问题谈论相同人物、组织、事件或主题。
- 证据充分性：候选是否覆盖用户实际要求的原子事实。

例如，“某组织通常使用债务和武力”和“该组织与某次危机有关”都高度相关，但二者不能自动拼成“该组织在这次危机中使用了债务和武力”。前者是排序问题，后者是事实蕴含问题。

### 2.3 Evidence Role

候选证据在本次请求中能够承担的职责：

- `complete / answer`：证据能够直接支持最小可用答案。
- `partial_or_related / uncertainty`：证据相关，但缺少关键事实；只能说明当前掌握到什么、缺什么。
- `not_applicable / creative_context`：用户明确要求创作，候选用于约束世界观和人物，不证明新事件已经发生。
- `none / discard`：候选不能帮助当前请求，或答案应来自其他域、实时信息或一般推理。

### 2.4 最小可证回答

完全由候选证据支持、能够正面回答用户核心疑问的最短提纲。它不要求穷尽所有背景，也不允许加入候选中没有的细节。

### 2.5 Missing Requirements

证据判定器列出的缺失原子事实，例如“纱织在求助老师之前对老师做过什么”。这些缺口可直接成为追加检索查询，而不需要维护剧情关键词或人物专用规则。

### 2.6 Evidence-driven Escalation

仅在首次证据不能形成最小可证回答、并且缺失事实可能存在于当前知识域时，扩大检索预算、增加图跳数或生成追加查询。它与“看到某个关键词就直接 deep”不同。

## 3. 实验问题

本轮回答四个问题：

1. BGE 分数能否单独承担知识域路由和回答许可？
2. 小型 LLM 能否区分完整证据、边界证据、创作背景和无关候选？
3. 从 `missing_requirements` 自动生成的深搜能否补齐事实？
4. 深搜是否会把同一实体的无关材料误当成缺失细节？

## 4. 样本设计

共 120 条：

- 60 条预期剧情知识问题：15 个事实族，每族使用中文直问、中文记忆外壳、英文、日文四种表达。
- 28 条同实体缺失细节：准确初次见面台词、早餐品牌、童年宠物、逐字遗言、生日礼物、鞋码等。
- 8 条私人记忆问题。
- 4 条公共记忆问题。
- 4 条闲聊。
- 4 条实时外部信息。
- 8 条角色扮演创作或貌似实时的任务/消息问题。
- 4 条无关一般知识问题。

这里的 `knowledge_supported` 是“知识库按设计应当支持该问题族”的粗标签，不等于“首次返回的前四条证据已经完整回答”。因此报告不把脚本输出的单一 accuracy 当成最终真值，而是分别审计召回、证据完整性、安全误接收和深搜收益。

## 5. 实验流程

### 5.1 基础探针

配置：

- 原问题直接检索，不删除“你记得”等外壳。
- `graph_hops=0`。
- `candidate_limit=20`。
- 使用已配置的 BGE cross-encoder reranker。
- 禁止 follow-up 和自动升级。

结果：

| 指标 | 结果 |
|---|---:|
| 总案例 | 120 |
| 知识正例证据命中 | 59/60，98.33% |
| 平均耗时 | 2.407 秒 |
| P95 | 2.977 秒 |
| 错误调用 | 0 |
| `score >= 0.05` 粗标签准确率 | 94.17% |
| 样本内最佳阈值 | 0.104646 |
| 最佳阈值粗标签准确率 | 95.00% |

`0.05` 的误接收包括：

- 找到白子相关材料，却没有第一次见面的准确台词。
- 找到星野与梦前辈的死亡和创伤，却没有逐字遗言。
- 找到老师可接受跨学园任务的背景，但用户要求的是新创作任务，不是已有事实。

这证明 BGE 高分代表“值得阅读”，不代表“可以据此断言”。

### 5.2 证据角色判定

第三版判定器增加 `grounded_answer_outline`：先尝试用候选形成最小可证回答，再决定是否完整。提示词只包含领域无关的证据规则，没有人物名、剧情名或本次数据库专用逻辑。

Qwen3.5-9B 第三版结果：

| 指标 | 结果 |
|---|---:|
| 案例 | 120 |
| 粗标签可回答性准确率 | 94.17% |
| 负例被误判为完整 | 0/60 |
| 预期知识问题首次判定完整 | 53/60 |
| 预期知识问题首次判定不足 | 7/60 |
| 平均判定耗时 | 4.736 秒 |
| P95 | 10.220 秒 |

两条看似创作的问题——“有哪些学生刚刚发消息”“现在有哪些新的出差任务”——被严格解释为当前事实查询并判为无证据；六条明确要求“生成、原创、invent、作って”的请求进入 `creative_context`。这不是故事规则问题，而是语言本身存在事实询问与角色扮演即兴创作的歧义。该歧义应由对话模式与最终回答模型决定，不能让知识证据判定器私自假定事件已经发生。

### 5.3 证据缺口深搜

选取范围：

- 9 个第二版初检未判完整的预期知识案例。
- 全部 28 个同实体缺失细节安全对照。

配置：

- 原问题保留为主查询。
- `missing_requirements` 作为 follow-up queries。
- `graph_hops=2`。
- `candidate_limit=80`。
- 最多输出 20 个 Episode、12 个 Concept、10 条路径。
- 仍使用 BGE reranker。

结果：

| 指标 | 结果 |
|---|---:|
| 深搜案例 | 37 |
| 平均深搜耗时 | 7.229 秒 |
| 深搜 P95 | 8.497 秒 |
| 每例平均新增 Episode | 11.216 |
| 9 个知识缺口升级成功 | 6 |
| 28 个缺失细节误补全 | 0 |

成功补齐的代表性证据：

- 星野/梦前辈：新增 Episode 154，明确梦前辈独自进入沙漠后死亡，成为星野长期自责与执着的根源。
- 未花责任：新增 Episode 42，明确未花因偏见、孤立感与政治选择参与破坏条约的计划，并面对审判和赎罪。
- 莉音/爱丽丝：新增 Episode 290、307，直接绑定“可能毁灭千年”的判断与隔离措施。
- 纱织/老师：新增 Episode 31、53，补出“曾射伤老师，后来为拯救亚津子求助”的完整事件链。

未解决的三项：

| 案例 | 类型 | 判断 |
|---|---|---|
| 凯撒在阿拜多斯债务危机中具体做过什么 | 知识内容缺口 | 当前候选只有凯撒的一般手段及其与危机有关，缺少“手段在该事件中实施”的直接绑定。判定不足是正确的。 |
| 梓加入补课部前与阿里乌斯是什么关系 | 判定过严 | 候选明确写有“前阿里乌斯成员”，已足以回答组织关系；9B 仍擅自要求人际互动细节。 |
| 联邦学生会长为什么没有继续主持事务 | 问题义务歧义 | 候选明确写有“会长失踪后出现权限空缺”。若问题只问直接状态，已经足够；若追问失踪机制，则剧情尚未确认。粗标签没有区分这两种读法。 |

### 5.4 稳定性复核

对 37 条深搜结果重复两次 Qwen3.5-9B 判定：

- 37/37 的“是否可作为事实回答”完全一致。
- 36/37 的完整证据角色完全一致。
- 唯一变化为一个不存在的婴儿时期细节在 `none/discard` 与 `none/uncertainty` 间切换，不会允许输出事实。

### 5.5 模型对照

| 模型 | 样本 | 平均耗时 | P95 | 负例误判完整 | 粗标签误拒绝 | 结论 |
|---|---:|---:|---:|---:|---:|---|
| Qwen3.5-9B v2 | 120 | 2.840 秒 | 6.268 秒 | 0 | 9 | 快，但偏保守 |
| Qwen3.5-9B v3 | 120 | 4.736 秒 | 10.220 秒 | 0 | 7 | 最小回答提纲改善 2 项，但独立调用仍偏慢 |
| DeepSeek-V3.2 | 120 | 7.758 秒 | 13.022 秒 | 0 | 12 | 更慢且在此任务上更保守 |
| Qwen3.5-35B-A3B | 37 | 未完成 | 多次超过 90 秒 | 未形成完整样本 | 未形成完整样本 | 约运行八分钟后终止，不适合在线独立判定 |

35B 对照被终止且没有形成完整结果文件，不能用于质量排名；它只提供了明确的在线延迟反证。

## 6. 架构结论

推荐的在线流程为：

```text
并行查询可能的记忆域
        ↓
向量召回 + BGE 排序
        ↓
一次回答模型调用同时输出 EvidenceContract 和回答草稿
        ↓
complete
    → 直接回答

partial + 缺口可能仍在当前域
    → 用 missing_requirements 深搜
    → 第二次最终回答

partial + 文档明确未收录/未确认
    → 说明当前证据边界

explicit creative
    → 候选只约束角色和世界观
    → 新剧情写入用户私人记忆，不伪装成原剧情事实

external/private/public
    → 交给对应域，不让剧情域阻塞
```

`EvidenceContract` 建议至少包含：

```json
{
  "intent_mode": "factual|creative|conversation|external_current",
  "claims": [
    {
      "claim": "原子主张",
      "evidence_ids": [1, 2],
      "status": "supported|partial|unsupported"
    }
  ],
  "grounded_answer_outline": "最小可证回答",
  "missing_requirements": [],
  "upgrade_recommended": false,
  "answer": "面向用户的回答"
}
```

关键点：证据合同应和回答共用一次模型调用。若为所有 standard 请求串联“Probe → 独立判定 LLM → 回答 LLM”，仅检索和判定就已接近或超过五秒目标；若再深搜，实测组件相加约为 16 至 19 秒，尚未包含最终回答。

## 7. 暂不采用的方案

- 不把 BGE 分数阈值当作回答许可。
- 不为“你记得、哪些事情、第一次、关系、为什么”继续增加表达词表。
- 不把所有 `partial` 无条件升级 deep；明确未收录的精确细节继续深搜只会增加延迟。
- 不用 35B 或 DeepSeek 作为每次请求的独立路由器。
- 不把创作背景写回剧情事实层；生成事件应记录在用户个人域，并带来源和推断属性。

## 8. 发现并修复的实验基础设施问题

1. 第一轮深搜在所有检索完成后因汇总 `round()` 参数错误而未落盘。已修复。
2. 原评测脚本只在整批结束后写文件，35B 超时对照被终止时丢失全部部分结果。
3. `run_evidence_role_judge.py` 与 `run_evidence_driven_followup.py` 已增加原子写入、分批 checkpoint 和未完成文件恢复。默认分别每 4 条和每 2 条保存一次。
4. 两个脚本及提示配置已通过 Python 语法检查。

## 10. 下一阶段验收条件

在接入线上主流程前，需要完成：

1. 将粗粒度 `knowledge_supported` 标签改成逐问题 `required_claims`、`minimum_answer`、`acceptable_partial` 和 `known_absent`，解决本轮两个问题义务歧义。
2. 把 EvidenceContract 合并进回答模型调用，比较“现有关键词选档”与“证据驱动升级”的端到端回答质量和耗时。
3. 加入私人、公共、剧情三个域同时有候选的样本，验证模型能逐条选择证据，而不是只选择一个域。
4. 加入角色扮演歧义样本，区分“查询当前真实任务”和“即兴生成新任务”，并验证生成内容只写入当前用户私人记忆。
5. 以端到端指标验收：缺失细节事实误答率为 0；知识问题最小答案覆盖率至少 95%；普通请求 P95 尽量不超过 5 秒；deep 任务单独记录升级收益与额外延迟。

本轮结论可以进入下一阶段 shadow 模式，但不足以直接删除现有生产路由或把独立证据判定 LLM 串到所有请求中。
