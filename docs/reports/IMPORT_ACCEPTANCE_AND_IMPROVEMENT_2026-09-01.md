# 导入机制验收与改进报告（2026-09-01）

## 结论

当前机制在本轮冻结的五文件 canary 范围内达到导入验收标准，可以继续用于扩大导入实验，但还不能据此宣称任意文档或完整剧情库都已验收。

- 5 个文件全部完成，拆为 9 个 Source、43 个 Episode；无失败任务。
- SQLite 完整性、float32 embedding、Source 证据映射、人物证据、跨 Source 重复和 Episode 覆盖严格审计全部通过。
- 22 个冻结问题的证据全部能从持久化 Episode 重新定位；纯 float32 BGE-M3、无增长边、无 reranker 时，Recall@20 为 100%，达到预先约定的 `>95%` 标准。
- 两个曾发生退化的文件独立重导后也通过严格审计；4 个针对性问题 Recall@10/20 均为 100%。未花样本由旧结果 rank 12 改善到 rank 5。
- 最终代码再次单独重导阿比多斯低排名文件：严格审计通过，3 个冻结问题全部 rank 1，且没有整批抽取拒绝或 JSON 修复模型调用。
- 最终代码通过 296 项单元测试和全量语法编译检查。

这里的“通过”特指：导入结构完整、Episode 可追溯、冻结证据不丢失、基础 Top-20 能召回。它不等于回答生成、增长边收益、全库时间线和 Concept 自动合并已经通过。

## 验收标准如何定义

### 1. 结构完整性

导入任务必须结束为 completed；Source、Episode、Concept、Association 不得出现外键悬空、非法 JSON、空内容或非 float32 embedding。1024 维 float32 embedding 的 BLOB 长度应为 4096 字节。

### 2. 可复现证据

每条 Episode 保存：

- `source_id` 与 `source_key`；
- `evidence_spans_json`：Source 内的行号范围；
- `evidence_quotes_json`：由这些范围重建的原文；
- `evidence_basis`：证据产生方式。

审计不相信 Episode 摘要本身，而是重新从 Source 按行号构造证据，检查范围是否合法、人物是否出现在自己的证据内、重叠分片是否制造重复 Episode。

### 3. 语义覆盖

覆盖检查允许省略标题、省略号和无信息短应答，但不允许：

- 连续 6 条以上的实质对白完全没有任何 Episode 引用；
- 一条信息密度高的关键句被遗漏。本轮阈值为清洗后字母/数字/汉字等信息字符至少 32 个。

覆盖门只判断“重要 Source 内容是否被某条 Episode 引用”，不把 Episode 数量当质量指标。

### 4. 冻结检索验收

问题在导入前固定；期望答案不绑定运行时 Episode ID，而是用 `source_key + evidence all_terms` 重新解析。因此换一个数据库重导后，验收仍然有效。

多事实问题的每个 matcher 是独立证据槽。该问题的 rank 取所有证据槽最佳 rank 中最差的一个；这避免“只命中一半事实也算成功”。

### 5. 人工语义抽查

机器指标之外，检查低排名 Episode 的摘要与证据，区分：

- 导入遗漏：关键原文没有进入任何 Episode；
- 摘要退化：证据存在，但 Episode 被写成过宽泛的“众人讨论”；
- 纯排序问题：Episode 和证据正确，只是 embedding 排名较低。

## 找到的根因与已实施改进

### 1. 模型的等价 JSON 表达被误判

模型曾把证据写成 `[[9], [10], [11]]`，旧解析器只接受 `[[9, 9], [10, 10], [11, 11]]`。内容正确却触发整批纠错，随后 7 条未花 Episode 被压成 2 条。

现在会：

- 接受 `[line]` 作为 `[line, line]`；
- 只对这种 singleton 表达合并连续行，避免因序列化冗长触发“超过 8 个范围”；
- 保持显式 `[n, n]` 列表原样，使原有防止逐行复制 Source 的限制继续生效。

### 2. 全批重试造成模型漂移

一个局部遗漏或一个人物声明错误曾让完整 Episode 列表重新生成。重试并不保证更好，反而会改变已经正确的边界。

现在对覆盖缺口执行局部补抽：保留已通过的 Episode，只要求模型补充与缺口行段相交的新 Episode，合并后重新跑全量证据审计。

### 3. 人物检查与蕴含审计顺序不一致

对于 audited profile，Episode 正文中的错误人物可以由后续蕴含审计删除或改回证据原名；但局部补抽路径仍在审计前拒绝该结果，造成无谓的整批重试。

现在主抽取与补抽采用相同策略：

- 仅出现在 participants、既不在正文也不在证据中的名字，确定性删除；
- 正文中的人物声明交给蕴含审计修订；
- 审计完成后再次执行严格人物证据检查，未解决的问题仍然失败关闭。

这不是放松最终标准，而是把可修复错误放到正确阶段处理。

### 4. 覆盖检查过去只关注长空洞

只检查连续长缺口会漏掉单独一行却决定答案的事实，例如资产决议权。现在同时检查长缺口和高信息单行，并且数据库审计会重新运行同一规则，防止只在导入时临时通过。

### 5. 重叠分片可能制造重复记忆

分片 overlap 原本可能把一个完整长 record 再复制到下一个 Source，随后生成两个几乎相同的 Episode。现在 overlap 受自然边界和最大长度约束；审计还会比较不同 Source 的证据，报告跨 Source 重复。

### 6. 行号格式导致无意义的 JSON 修复调用

模型常把行号输出为裸 token：`[L0005, L0008]`。这不是合法 JSON，过去会再次调用推理模型，只为加引号。

现在 JSON 解析器会在字符串之外确定性地把裸 `Lxxxx` 变为字符串，然后沿既有类型层转换成整数；字符串正文中的 `[L0009]` 不会被改写。提示词也简短明确要求输出 JSON 整数 `[5, 8]`。只有本地规则仍无法解析时才调用模型修复。

v30 与 v31 日志共出现 6 次 JSON 修复调用；并非能证明它们全部来自裸行号，但其中这一明确类别以后不再产生额外 API 调用。

### 7. 避免用剧情特例修提示词

所有改动都围绕通用不变量：证据范围、语义角色、覆盖、人物局部证据、JSON 形状和失败阶段。没有加入“老师不是会长”或某个剧情角色的硬编码规则。摘要提示只增加一条通用要求：保留专名、数字、独特称呼和核心对比，不得用“讨论了/表示反应”替代具体主张。

## 仍未解决的问题

1. **小 Top-K 不能成为导入硬门槛。** 最终复验把“两个傻瓜”从 rank 7 提升到 rank 1，但五文件运行的 R@5 仍只有 90.91%，且模型重导存在随机性。生产策略仍应保留 Top-20/30，再交给 BGE reranker 和 Coverage Selector；不应继续拉长导入提示词来追求每题 Top-1。
2. **单条短关键句仍可能漏过启发式。** 32 个信息字符阈值是保护网，不是语义完备证明。扩库时仍需冻结更多证据问题。
3. **多语言摘要风格不完全一致。** 同一库中可能出现中文叙述配日文人名，BGE-M3 能跨语种召回，但小 Top-K 会受影响。Concept alias 能缓解，尚未证明最佳规范化策略。
4. **Source 级原子提交/可恢复性仍需加强。** 本轮验证了完成状态和失败汇总，但没有实现真正的 exactly-once；此前已按要求取消幂等导入目标，因此报告不把它算作通过项。
5. **Concept 跨语言去重仍是实验机制。** 本轮只确认没有结构冲突，未证明自动合并不会错合。
6. **增长边未参与本轮检索。** 导入时延后了推断型 Episode-Episode / Concept-Concept 关系，以隔离 Episode 基础质量。增长边收益与 generation 控制需要单独实验。
7. **不是完整语料结论。** 五文件 canary 用于高密度发现错误；全量 `production_kb` 与 `serihu` 仍需分批导入并持续抽样审计。

## 建议的后续导入门禁

每批导入保持以下顺序：

1. 先选 1—2 个格式代表文件预检和导入；
2. 运行 strict audit，任何证据、覆盖、人物或重复问题都停止扩批；
3. 运行该批冻结证据问题，要求 unresolved 为 0 且 Recall@20 ≥ 95%；
4. 人工检查最差 rank 与最长 Episode，确认是排序问题而非摘要退化；
5. 才扩大并发和文件数；推断型 Association 在基础层验收后单独构建。

当前结果支持继续扩大导入，但必须保留上述门禁和隔离数据库，不能以“导入命令返回 completed”替代质量验收。
