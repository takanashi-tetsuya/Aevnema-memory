# 跨域回答合同与候选绝对门实验报告

日期：2026-09-01

## 1. 结论摘要

本轮没有得到“新链路已经可以直接替换生产链路”的结论，但找到了一个比继续增加提示词更重要的架构问题，并验证了有效改进方向。

核心结论：

1. 把证据审计与自然回答合并为一次模型调用是可行的。使用“短 JSON 合同在前、自然回答在后”的分帧协议后，6 题小样本达到独立盲评 6/6，且不再出现自然回答破坏 JSON 的问题。
2. 当前小数据库快速路径会关闭 reranker，并把内部相对排序分数继续表现为 `top_score`。无关私人/公共候选因此也会出现约 `0.997` 的分数。这不是 BGE 的分数，而是分数语义混用。
3. BGE reranker 本身在同语种直接事实上表现良好：6 个正例 Top-1 全对，正例最低分 `0.4051`，4 个无关查询最高分仅 `0.0021`。
4. 在保存的 17 题候选上增加 `0.05` 绝对相关性门后，Qwen 的机器验收由原始 10/17、协议容错后 11/17，提升到 15/17；协议解析失败为 0。
5. 单一绝对阈值不能覆盖多语言与开放创作。日语问题对应中文私人证据时，正确候选虽然仍排第一，但分数只有 `0.0021`；开放创作的世界观背景也通常低于直接事实阈值。
6. 每请求增加一次远端 Qwen 语义规划不是合适的默认路径：6 题中域选择正确 5/6，平均仅规划就耗时 15.93 秒，总链路中位数 28.05 秒。
7. 更强模型能提高证据理解上限，但不适合全量默认调用。在相同未过滤候选上，DeepSeek 的机器验收为 15/17，生成中位数 19.26 秒；Qwen 协议容错后为 11/17。
8. 证据候选和创作背景候选必须拆成两条通道。严格门适合判断“什么可以当事实”，但不能把低直接相关度的世界观背景全部删除，否则角色扮演会退化成脱离作品的通用创作。

因此，下一版推荐结构不是“所有候选 Top-K 直接交给回答模型”，也不是“每次先调用一个 LLM 路由器”，而是：

```text
各域低成本召回
    ↓
Support Lane：BGE 绝对相关性门，供事实主张引用
Context Lane：人物/世界观/会话锚点，供角色扮演约束，不证明事件已发生
    ↓
一次回答调用输出 EvidenceContract + 自然回答
    ↓
本地验证协议、证据 ID、域范围与 answerability
    ↓
证据不足或事实蕴含可疑时，才升级 DeepSeek / deep retrieval
```

本轮全部操作使用知识库副本和合成私人/公共记忆，没有写入机器人的正式记忆数据库。

## 2. 名词定义

### 2.1 EvidenceContract

与用户回答同时生成的机器可读合同。它记录：

- 本轮是事实查询、创作、普通对话还是实时外部请求；
- 哪个记忆域承担事实支持、背景或应被拒绝；
- 回答中的原子主张及其证据引用；
- 当前证据是否完整；
- 是否需要追加检索；
- 新内容应写入私人域还是知识域。

本轮最终采用分帧协议：

```text
<CONTRACT>{短 JSON}</CONTRACT>
<ANSWER>自然回答</ANSWER>
```

相比把自然回答塞进 JSON 字符串，它减少了引号、换行和长文本重复导致的解析失败。

### 2.2 Support Lane

可以直接支持回答事实主张的候选集合。候选进入这一通道必须通过较严格的绝对相关性或证据完整性判断。回答中的 `supported` 主张只能引用这里的证据。

### 2.3 Context Lane

只用于约束角色、地点、世界观和语气的背景集合。它可以帮助生成符合设定的新任务或消息，但不能证明这些新事件在原作或历史对话中已经发生。

### 2.4 绝对相关性门

根据 cross-encoder 输出的绝对 `relevance_score` 删除低相关候选。它与 Top-K 不同：

- Top-K 无论候选多差都必须留下若干项；
- 绝对门允许结果为空；
- 空结果对私人来源核验、实时请求和普通寒暄尤其重要。

### 2.5 小数据库快速路径

当某域 Episode 数量不超过配置阈值时，系统跳过复杂规划和 reranker，直接把小库候选交给回答模型。这样能够降低调用成本，但“数据库很小”不等于“每条内容都与当前问题有关”。

### 2.6 分数语义

当前链路中至少存在三种不能互换的分数：

- 向量余弦：query embedding 与候选 embedding 的几何相似度；
- 融合/排序分数：向量、稀疏检索、图扩展等通道融合后的相对排序值；
- cross-encoder relevance score：query 与候选文本成对判断后的相关性值。

只有最后一类在经过校准后可以用于绝对相关性门。将融合分数命名为统一的 `top_score` 会误导后续质量判断。

### 2.7 Answerability

本轮合同新增四种回答状态：

- `complete`：现有证据覆盖了问题要求；
- `insufficient`：仍缺少关键事实，只能说明边界；
- `creative`：用户要求的新内容已经完成创作；
- `not_applicable`：普通寒暄或无需记忆的开放对话。

## 3. 实验目标

本轮回答以下问题：

1. 能否把现行“回答、审计、改写、再审计”缩成一次回答合同调用？
2. 三个域全部检索后交给模型，是否会造成私人、公共、剧情范围污染？
3. 使用远端小模型作为请求前规划器，能否同时改善质量和延迟？
4. Qwen 与 DeepSeek 的证据理解差异有多大？
5. BGE 高分异常来自模型本身，还是当前小库快速路径？
6. 增加绝对相关性门后，事实回答、创作和多语言分别发生什么变化？

## 4. 测试环境与样本

### 4.1 隔离环境

- 复制正式剧情知识库到实验目录；
- 创建独立公共数据库；
- 创建两个合成用户：平台不同但数值 ID 相同，用于验证平台隔离；
- 禁止知识、公共和用户增长写入；
- 回答协调器使用 `defer_commit=True`；
- 所有实验结果写入 `validation/`。

### 4.2 合成事实

- 私人暗号：`灰蓝鲸 -314`；
- 私人饮品偏好：`无糖茉莉茶`；
- 公共问候语：`星光归航`。

### 4.3 17 类请求

覆盖：

- 中文、英文、日文私人事实；
- 同 ID 不同平台隔离；
- 公共事实；
- 私人 + 公共混合问题；
- 日奈职务直接事实；
- 纱织因果链；
- “你还记得白子”剧情回忆外壳；
- 当前知识库未收录的精确初次见面原话；
- “我以前是否说过某剧情事实”的来源冲突；
- 显式新消息创作；
- 隐式当前新任务创作；
- 日语阿拜多斯任务创作；
- 阿拜多斯出差建议；
- 东京实时天气；
- 普通寒暄。

## 5. 合同协议迭代

### 5.1 JSON 内嵌回答

初始设计把合同与自然回答都放进一个 JSON。Qwen 两次在 `answer` 字符串中发生重复生成，最终破坏 JSON。候选和主张其实已经正确，但整条结果无法使用。

这说明自然回答不是适合长期放在严格 JSON 字符串中的字段，尤其在小模型、长候选和多语言场景中。

### 5.2 分帧短合同

改为短合同 + 自然文本后：

| 版本 | 小样本 | 机器验收 | 独立盲评 | 解析失败 |
|---|---:|---:|---:|---:|
| v2 JSON 内嵌回答 | 6 | 3/6 | 4/6 | 2 |
| v3 分帧合同 | 6 | 5/6 | 5/6 | 0 |
| v4 加入事实槽、身份和语言 | 6 | 5/6 | 6/6 | 0 |

v4 唯一机器失败是日语回答把不可翻译的暗号从简体改成繁体。随后增加“不透明字面值逐字复制”原则，完整实验中的日语暗号被正确保留。

### 5.3 完整 17 题 A/B

| 指标 | 现行回答链 | 一次合同链 |
|---|---:|---:|
| 机器验收 | 12/17 | 10/17 |
| 独立盲评 | 5/17 | 10/17 |
| 平均耗时 | 15.46 秒 | 10.41 秒 |
| 中位耗时 | 6.40 秒 | 10.06 秒 |
| 5 秒内 | 5/17 | 0/17 |

机器验收主要检查必需词、域、意图、写入目标和证据 ID；独立盲评还会检查事实与范围。两者差异说明不能把关键词脚本通过率当作整体回答质量。

现行路径出现一次 161.67 秒长尾，因为回答触发了多轮私人记忆审计/改写。一次合同链消除了这种多调用放大，但远端检索加回答仍没有达到 5 秒目标。

## 6. 失败模式分析

### 6.1 无关候选污染

三个域无条件送入回答模型会产生：

- 跨平台私人记忆缺失时主动推荐公共问候语；
- 核验“我有没有说过白子喜欢草莓牛奶”时，顺带背诵用户喜欢茉莉茶和私人暗号；
- 阿拜多斯建议中插入无关私人暗号；
- 普通早安时主动复述私人偏好。

这些问题不是“没有规则告诉模型怎么回答”，而是候选输入本身缺少空结果机制和范围分层。

### 6.2 存在证据 ID 不等于主张被证据蕴含

Qwen 在日奈题中引用了明确写有“风纪委员会委员长”的 Episode，却生成“学生会长”或“副委员长”。本地验证只能确认 ref 存在，不能确认 claim 与 ref 内容一致。

因此生产合同至少还需要一种主张—证据蕴含检查：

- 对直接职务、身份、否定和数字做轻量一致性检查；或
- 证据合同出现高风险关系字段时升级更强模型；或
- 在 deep 路径执行原子主张审计。

不能继续把“引用了某个 ID”视为事实正确。

### 6.3 创作缺少世界观背景通道

严格门把无直接事实相关性的知识全部删除后，Qwen 能正确判定请求是 `creative` 并写入私人候选，但生成内容可能变成北境极光、通用数学作业、深海遗迹等脱离当前角色世界的任务。

这些案例在当前机器验收中仍可能通过，因为脚本只检查 `creative` 和私人写入，不足以判断角色扮演质量。它们不能被报告为真实质量通过。

正确做法是保留单独的 Context Lane，并同时传入正式 persona，而不是降低 Support Lane 阈值。

### 6.4 多语言绝对分数漂移

日语问题“以前告诉你的合言葉”对应中文私人证据时：

- 正确候选仍为 reranker Top-1；
- relevance score 只有 `0.00210987`；
- 第二名公共问候语为 `0.00184805`；
- 正确候选向量余弦为 `0.50187`，但无关查询最高余弦达到 `0.52399`。

所以：

- 单一 `0.05` 阈值会误删跨语种证据；
- 单一余弦阈值无法补救；
- 无条件使用相对 Top-1 又会把不存在的私人事实重新召回。

需要单独评估跨语种 query expansion、域内相对排序与绝对门的组合，不能直接修改一个全局阈值。

## 7. 请求前模型规划实验

复用项目现有 `MemoryIntentPlanner`，让 Qwen 输出域、查询、实体和回答事实槽，再只检索选中域。

6 题结果：

| 指标 | 结果 |
|---|---:|
| 完全正确的规划 | 5/6 |
| 平均规划耗时 | 15.93 秒 |
| 合同独立盲评 | 5/6 |
| 总链路平均耗时 | 28.49 秒 |
| 总链路中位耗时 | 28.05 秒 |

失败案例是“公共问候语和个人暗号分别是什么”：规划器正确列出了两个事实槽，但只启用 private，漏掉 public，回答随后编造了公共问候语。

结论：远端 Qwen 规划可以作为语义上限参考或复杂请求的可选步骤，但不能作为每轮默认调用。它既没有达到 100% 域覆盖，也明显恶化延迟。

## 8. 同候选模型能力对照

完全复用 17 题已保存候选，不重新检索：

| 指标 | Qwen 原始 | Qwen 新解析器重放 | DeepSeek |
|---|---:|---:|---:|
| 机器验收 | 10/17 | 11/17 | 15/17 |
| 解析失败 | 4 个协议/格式相关失败中的多数不可用 | 容错后改善 1 题 | 0 |
| 生成平均耗时 | — | — | 18.49 秒 |
| 生成中位耗时 | — | — | 19.26 秒 |
| 加原 Probe 的预计中位耗时 | — | — | 24.36 秒 |

DeepSeek 的两个机器失败中：

- 日奈回答为 `Chairman of the Disciplinary Committee`，独立盲评认为语义正确，但测试要求官方英文 `Prefect Team`；
- 私人来源冲突题虽然正确否定了“用户曾说过”，仍顺带提到无关茉莉茶，导致域脚本认为私人 supported 范围超出。

独立 Qwen judge 有若干批次返回不完整结果，因此该次 `12/17` judge 汇总不能作为严格模型排名；报告以完整机器字段和逐题人工复核为主。

## 9. BGE 校准与分数语义问题

### 9.1 同语种直接事实

6 个正例、4 个负例，统一 6 文档候选池：

| 指标 | 结果 |
|---|---:|
| 正例 Top-1 | 6/6 |
| 正例最低最佳分 | 0.40508 |
| 正例最佳分中位数 | 0.86197 |
| 负例最高分 | 0.00212 |
| 负例最高分中位数 | 0.000135 |
| 正负分数重叠 | 否 |
| 单次调用平均耗时 | 0.70 秒 |

这证明 BGE 不是此前 `0.997` 异常的来源。

### 9.2 加入跨语种与开放背景

加入日语暗号和日语阿拜多斯创作背景后：

- 正例 Top-1 降为 7/8；
- 正例最低分降到 `0.00002886`；
- 正负分数发生重叠；
- 原始 embedding cosine 也发生重叠。

域语义包装能够改善某些建议/背景排序，但无法代替域选择。例如给私人问题强行加“公共共享记忆”前缀，会让公共候选获得 `0.1361` 的虚假高分，因为 query 本身已经要求模型在公共域中找答案。

结论：域包装只能在域已经选对之后使用，不能自己决定哪个域有资格回答。

## 10. 候选绝对门实验

在 17 题保存候选上，用原问题重新进行一次跨域 BGE 打分，只保留 `score >= 0.05` 的候选。

| 指标 | 结果 |
|---|---:|
| 17 题过滤墙钟时间 | 3.76 秒 |
| 过滤后零候选 | 8/17 |
| Qwen 机器验收 | 15/17 |
| DeepSeek 机器验收 | 13/17 |
| 两模型解析失败 | 0 |

Qwen 的两个失败：

1. 日语暗号：正确中文私人证据被绝对阈值删除；
2. 日奈职务：保留了正确证据，但 Qwen回答成副委员长。

绝对门的明确收益：

- 私人来源冲突题不再背诵茉莉茶或暗号；
- 实时天气得到真正零候选；
- 显式创作不再把旧剧情当成已经发生的新消息；
- 协议输出更短，解析稳定。

但 15/17 只是结构化机器验收，不是完整角色扮演质量：开放创作在失去 Context Lane 后出现脱离世界观的问题。

该脚本初版把并发排队时间计入单题生成时间，所以文件中的 Qwen/DeepSeek `generation_mean_seconds` 和 `median` 不可用于模型延迟结论。过滤墙钟时间、总回答墙钟时间和其他独立实验的模型生成时间有效。脚本已修正计时位置，后续运行会分别记录 queue 与 model 时间。

## 11. 推荐架构

### 11.1 检索层

每个候选必须保留明确分数类型：

```json
{
  "vector_cosine": 0.62,
  "fusion_score": 0.99,
  "cross_encoder_score": 0.41,
  "cross_encoder_executed": true,
  "score_calibration": "same_language_direct_fact_v1"
}
```

`RetrievalQuality.top_score` 不能再混用不同类型分数。若未执行 cross-encoder，就不能使用融合分数通过绝对证据门。

### 11.2 小库路径

小库可以跳过 LLM 规划和图扩展，但不应默认把全库都交给回答模型：

```text
小库全量候选
    ↓
一次 BGE 成对评分（实测约 0.7 秒）
    ↓
允许真正空结果
```

如果配置为空，才完全关闭 reranker；启用 BGE 时，light 和 small-db 都应使用它。

### 11.3 双候选通道

```text
Support Lane
    直接事实、私人来源、公共约定、剧情主张
    严格相关性与来源门
    可以被 claims 引用

Context Lane
    persona、当前会话锚点、人物/地点/世界观背景
    允许较宽召回或关联漫游
    不能证明新事件已发生
```

开放创作的 `writes.private` 应保存实际生成的任务或消息，而不是 `student_message_1` 之类占位符。知识域写入继续要求至少两条直接 Episode 支持。

### 11.4 回答层

- Qwen 默认承担 light/standard 回答合同；
- 本地解析器允许枚举示例误抄和缺失结束标签的安全恢复；
- 本地拒绝不存在的 evidence ref；
- 高风险身份、职务、否定、数量、时间或因果主张需要额外蕴含检查；
- 只有证据不足、冲突、多跳缺槽或蕴含检查失败时升级 DeepSeek；
- 不再为每个请求串联独立 LLM 规划、回答、审计、改写、再审计。

### 11.5 多语言

多语言不能只依赖一个全局阈值。建议下一轮对照：

1. 原问题；
2. 只做语言归一化、不改专名与不透明字面值的检索查询；
3. 每域 query expansion；
4. strict absolute gate + 跨语种低分 Top-1 候选复核；
5. 低分候选只进入 `uncertainty`，不得直接成为 supported。

必须在中文、日文、英文混合证据上单独报告 recall、误接收和私人域泄漏，不能用同语种阈值外推。

## 12. 生产改动优先级

| 优先级 | 改动 | 原因 |
|---|---|---|
| P0 | 分离 `fusion_score` 与 `cross_encoder_score` | 当前 `top_score` 语义混用会造成错误质量判断 |
| P0 | 小库启用 BGE 绝对相关性门并允许空结果 | 直接消除无关私人/公共候选污染 |
| P0 | 引入 Support / Context 双通道 | 同时保证事实可信度和角色扮演世界观 |
| P0 | 使用分帧 EvidenceContract 并做本地引用校验 | 减少现行多轮审计和 JSON 失败 |
| P1 | claim↔evidence 蕴含复核与证据不足升级 | 防止“引用正确 Episode 但写错职务” |
| P1 | 多语言阈值与 query expansion 专项评测 | 当前日语→中文证据会被绝对门误删 |
| P1 | persona 正式进入合同回答上下文 | 防止零候选创作脱离角色世界 |
| P1 | 私人创作写回保存完整内容 | 保证后续连续角色扮演可复用 |
| P2 | 请求级 deadline 和长尾降级 | 现行链路出现 161 秒长尾 |
| P2 | 远端 LLM planner 只作为 deep 可选步骤 | 默认使用质量/延迟均不划算 |

## 13. 下一阶段预注册标准

下一阶段在修改生产链路前，建议先完成至少 100 条分层样本：

- 25 条私人直接事实与 25 条同实体错误归因；
- 15 条公共/私人混合；
- 15 条中文问题检索日文/英文证据及反向组合；
- 10 条剧情直接事实与多跳事实；
- 10 条开放角色扮演创作和建议。

建议验收门槛：

- 私人错误归因事实输出：0；
- public/knowledge 代替私人历史：0；
- 同语种 direct fact Support recall@20：不低于 95%；
- 跨语种 direct fact Support recall@20：先测基线，再以不低于 95% 为目标；
- 合同无效 ref：0；
- 创作写入 knowledge：0；
- 创作世界观人工盲评通过率：不低于 90%；
- light 中位数目标继续为 5 秒，但必须分别报告 embedding、reranker、回答模型和排队时间。

## 15. 当前判断

当前最值得进入生产实验分支的不是远端模型规划器，也不是更长的提示词，而是以下三个小而明确的架构改变：

1. 修正分数语义，确保小库也能获得真实 BGE relevance score；
2. 将事实证据和创作背景分成 Support / Context 两条通道；
3. 使用分帧 EvidenceContract 合并回答与审计，只在证据不足或蕴含风险时升级。

这三项分别解决“错误候选进入”“正确背景被严格门删除”和“回答链调用次数膨胀”，并且都不依赖蔚蓝档案人物或剧情专用规则。
